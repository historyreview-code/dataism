# 时辰 · Twelve Hours

**Dataism 系列陈列展品 · 2026**

> 五万个粒子，在一昼夜里换十二次颜色与性情。
> 你的鼠标与现场的声音，是它唯一的天气。

---

## 一、作品陈述

《时辰》是一件以**中国传统十二时辰**为叙事骨架的数据粒子艺术装置。

在原作 Dataism — 17（五万粒子、鼠标扰动、点击涟漪、六种合成音景）的引擎之上，本作引入了"时间"作为策展人：每**两个小时**，作品自动切换到一个新的时辰章节——配色、粒子行为、音景、诗句与数据叙事随之整体过渡。观众在任何时刻走进展厅，看到的都是"此刻"的那一幕；停留一昼夜，才能看完全部十二幕。

作品的深层命题是：**数据不是冷的。** 互联网流量有昼夜节律，潮汐按月球时刻表进退，风暴起于青萍之末，鱼群在远方转向——当我们把一天切回十二时辰，那些看似抽象的数据流，便重新获得了古人对时间的身体感。

互动即天气：
- **鼠标移动**——拨动粒子云，如风过水面
- **点击**——发送一圈涟漪冲击波
- **现场声音（麦克风）**——观众说话、鼓掌、环境声实时驱动粒子涨落（`?mic=1`，只监听不外放）
- **互动强度**——越活跃，音景越明亮；静止，作品渐入低语

一日之计在晨，一作之计在午：粒子速度、噪声幅度、互动响应在**午时**达到峰值（flow 0.070 / mouse 2.2），在**丑时**降到最低（flow 0.030 / mouse 0.9）——作品自身的代谢曲线。星云的可见动态来自「轨道场」：粒子沿椭圆带做差速摆动（密度波呼吸——午时摆幅 0.34 rad / 节奏 0.34 rad/s，丑时仅 0.11 / 0.10），相位随半径偏移形成旋臂扫过的层次，水平剪影永不变形。夜章采用「月蓝 × 暖琥珀」双色系：冷月光与暖钠灯的城市夜景，让蓝橙对比的生命感延续到深夜。

## 三、运行与陈列

### 3.1 在线展示

```
pnpm dev:exhibit        # → http://localhost:5176
pnpm build:exhibit      # 静态产物 → apps/dataism-exhibit/dist/
```

### 3.2 现场陈列（kiosk 模式）

```
http://<host>/?kiosk=1&mic=1&audio=1
```

| 参数 | 作用 |
|---|---|
| `?kiosk=1` | 隐藏光标与全部 UI 铬；首个手势自动全屏；Screen Wake Lock 防息屏；禁右键 |
| `?mic=1` | 启用麦克风：现场声实时驱动粒子（只监听，绝不外放，无啸叫） |
| `?audio=1` | 启用合成音景（跟随时辰自动切换） |
| `?duration=N秒` | 演示模式：每 N 秒切一章（合成时钟，布展验收用） |
| `?chapter=午` | 钉住某个时辰（媒体预览 / 拍宣传照用） |
| `?mode=storm` | 手动指定音景（覆盖"跟随时辰"） |

键盘：`F` 全屏 · `N` 强制下一辰 · `I` 作品陈述卡。

### 3.3 待机自演（吸引模式）

45 秒无任何输入，作品进入**自我表演**：一枚无形之光标开始自动巡游粒子云，每 8 秒激起一朵随机涟漪。任何真实输入立即接管。用于画廊无人时的"活橱窗"。

### 3.4 硬件封装建议（未来展品化）

- 屏幕：43–65" 4K 竖横皆可，亮度 ≥400 nit（粒子为暗底高光点，对比需求高）
- 主机：Mac mini / NUC（Chrome kiosk 全屏，`?kiosk=1&mic=1&audio=1` 开机自启）
- 拾音：指向性 USB 麦克风（观众区），避免音箱直对
- 音箱：隐藏式近场一对即可（音景动态范围 -14 ~ +6 dB，不需大功率）
- 家庭版：iPad 支架 + 蓝牙音箱，同一 URL

## 四、技术纵深（工程深度）

1. **引擎与作品分层**：`@studio/dataism-core`（粒子引擎 / GLSL / Tone.js 音频引擎 / React 组件）与作品层（十二时辰数据、策展 UI）完全解耦。第 N 号衍生作品 = 一份 `chapters.js` 风格的章节表 + 一个 app 壳。
2. **主题化 shader**：调色板与行为参数以 uniform 注入顶点/片元着色器，换主题用 `THREE.Color.lerp` + 标量指数趋近（时间常数 4s）在 GPU 侧平滑过渡，**不重建 50k 几何体**——两小时一换的章节过渡零成本。
3. **确定性粒子分布**：mulberry32(20260826) 种子 PRNG——每次刷新、每台机器、每件展品的粒子分布完全一致。这是"版画编号"式的一致性：不同展厅里的《时辰》是同一件作品。
4. **双时钟章节引擎**：真实时钟（2h/章，正式陈列）与合成时钟（durationMs 快放，布展验收/演示）同构复用；`forceNext()` 支持真实时钟下的跳章演示。
5. **多路音频合并**：Tone.js 合成音景频谱与麦克风现场声，逐频段（low/mid/high/beat）取最大值共同驱动粒子——艺术家的声音与观众的声音在同一片云上叠加。
6. **声音安全设计**：麦克风 analyser 永不接入 destination——现场声只进不出，结构上杜绝啸叫。
7. **音随章换**：AudioController 契约化（1s 淡出 → dispose → 2s 淡入），章节切音在后台完成，观众只感到"天色变了，声音也变了"。

## 五、版本与保护（护城河）

- **版本锚点**：git tag `dataism17-v1.0`（原作锁定）、`exhibit-v1.0`（本作锁定）。任何展出的版本可溯源、可复现。
- **确定性 = 可鉴定**：种子固定的粒子分布 + 固定的章节表 = 作品有"指纹"。两份渲染逐帧一致即可证明同源。
- **引擎即资产**：`dataism-core` 是持续积累的引擎（shader、音频图、章节引擎、kiosk 行为），衍生作品边际成本递减，后来者难以一比一复刻整个系列的一致性。
- **数据叙事预留**：巳时（NOAA GFS 风场）、未时（GBIF 洄游）已留接口位——真实数据接入后，作品从"诗意模拟"升格为"实时数据艺术"，护城河从实现难度升级为数据管线。
- **版权**：代码与内容保留所有权利；展示与授权联系作者。
